# 06 — Техника и Godot

Как проект устроен технически на Godot 4.4 и как правильно с ним работать
(включая работу с ИИ-помощником).

## Стек
- **Godot 4.4** (рендер GL Compatibility — лёгкий, под встроенную графику Intel).
- Язык — **GDScript**.
- Репозиторий: github.com/kalas12/zombie-rush.
- ОС разработки: Ubuntu 24.04.

## Почему Godot (а не Phaser)
Перешли с Phaser 3, потому что Godot даёт из коробки то, что в Phaser писалось руками:
- **Визуальный редактор** — локации, стены, дом, спавн ставятся мышкой.
- **Сцены** — лес / город / бой / карта кампании / меню — каждая отдельная сцена,
  переключение одной строкой.
- **Встроенная физика** — коллизии (`CharacterBody2D` + `move_and_slide()`),
  никакого ручного выталкивания из стен.
- **Встроенная навигация A*** — `NavigationRegion2D` + `NavigationAgent2D`,
  зомби сами обходят препятствия. (В Phaser это был бы отдельный модуль pathfind.)
- Экспорт в веб (itch.io), десктоп, мобилки.

## Ключевые узлы (что за что отвечает)
- **CharacterBody2D** — «тело персонажа» (зомби, потом люди). Двигается через
  `velocity` + `move_and_slide()`, само упирается в препятствия.
- **StaticBody2D** — неподвижное твёрдое тело (стены, пока и человек-заглушка).
- **CollisionShape2D** — форма столкновения (нужна каждому телу; без неё —
  предупреждение «no shape»).
- **Sprite2D** — картинка (текстура юнита).
- **NavigationRegion2D** — область, по которой можно ходить (запекается «Bake»,
  вырезает стены).
- **NavigationAgent2D** — «штурман» на зомби: считает путь в обход стен.
- **ColorRect** — цветной прямоугольник (плейсхолдер вместо картинок).

## Архитектура — главный принцип (сохраняем из старого проекта)
**Логику держим отделяемой от движка.** Числа баланса — в одном месте (см. «04»),
чтобы правились без копания в узлах. Типы зомби, перки, реликвии — данными
(наборы полей / ресурсы Godot), а не ветками if по коду. Это страховка и для
возможного будущего переноса, и для быстрого добавления контента.

## Группы (важный приём Godot)
Вместо поиска узлов по имени используем **группы**:
- Цель зомби — узлы в группе `target` (сейчас там Human).
  Зомби ищет: `get_tree().get_first_node_in_group("target")`.
- Стены для навигации — группа `navigation_polygon_source_geometry_group`
  (её запекает NavigationRegion2D). КАЖДАЯ новая стена должна быть в этой группе,
  иначе навигация её не увидит.
Группы делают код устойчивым к перестройке дерева сцены.

## Навигация — как настроить (памятка)
1. На сцене боя есть `NavigationRegion2D` с запечённым полигоном (область ходьбы).
2. Стены (`StaticBody2D`) — в группе `navigation_polygon_source_geometry_group`.
3. После изменения стен — нажать **Bake NavigationPolygon** на NavigationRegion2D.
4. Проём (дверь) делать ШИРОКИМ (80–100px), иначе навигация «зарастит» его
   радиусом агента и путь внутрь не построится.
5. Зомби (`zombie.gd`): в `_ready()` обязательно `await get_tree().physics_frame`
   перед первым запросом пути (навигации нужен кадр на инициализацию), иначе стоят.
6. Движение: `agent.target_position = цель` → `agent.get_next_path_position()` →
   едем к этой точке. Проверять `agent.is_navigation_finished()`, чтобы не толкать цель.

## Работа с ИИ-помощником (ВАЖНЫЕ ПРАВИЛА)
ИИ (в VS Code: Cline/Continue) подключён к папке проекта и помогает с кодом.
Горький опыт показал правила:

**1. ИИ пишет ТОЛЬКО скрипты (.gd). НЕ трогает сцены (.tscn).**
Формат .tscn капризный, ИИ его ломает (сцена не открывается). Сцены строим
мышкой в Godot сами. Всегда явно писать ИИ: «не редактируй .tscn, только .gd».

**2. Сначала ИИ ИЗУЧАЕТ проект, потом пишет.**
В промте требовать: прочитать project.godot, нужные .gd и структуру .tscn,
описать понимание, дождаться подтверждения — и только потом менять код.

**3. Если для работы нужно что-то в сцене — ИИ пишет ТЕКСТОМ, что нажать мышкой,
   а не лезет в файл.**

**4. Правки по одному файлу, с объяснением** (проект новичковый).

**5. Всё коммитить в git до крупных правок** — если ИИ сломает, откат:
   `git checkout <файл>`.

Если Godot показал «Files have been modified outside Godot»:
- если менял сам в Godot после сохранения → осторожно, можно потерять; проверить.
- если правил только ИИ и сцену не трогал → «Reload from disk».
- если сомнение → «Ignore external changes» + проверить/откатить через git.

## Диск и производительность (была проблема)
Диск был забит на 96% — это вызывало зависания тяжёлых инструментов.
Держать свободным хотя бы 5–10 ГБ. Чистка: `sudo apt clean`, `sudo apt autoremove`,
убрать старые node_modules от Phaser-версии, `journalctl --vacuum-time=3days`.
Godot сам лёгкий, но ИИ-редакторы требовательны — на забитом диске виснут.
