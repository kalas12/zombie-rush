# 06 — Техника, стандарты и правила работы

Как проект устроен на **Godot 4.4 / GDScript** и по каким правилам с ним работать.
Объединяет бывшие «06 — Техника», «08 — Best practices» и «Промт для ИИ».

---

## 1. Стек
- **Godot 4.4**, рендер GL Compatibility (лёгкий, под встроенную графику Intel).
- Язык — **GDScript**.
- Репозиторий: github.com/kalas12/zombie-rush. ОС разработки: Ubuntu 24.04.
- Godot-бинарь: `~/Downloads/Godot_v4.4-stable_linux.x86_64`.

Перешли с Phaser 3 ради того, что Godot даёт из коробки: визуальный редактор
локаций, сцены, встроенная физика (`CharacterBody2D` + `move_and_slide()`),
встроенная навигация A* (`NavigationRegion2D` + `NavigationAgent2D`),
экспорт в веб/десктоп.

## 3. Именование (строго)
- Папки и файлы: `snake_case` → `zombie_type.gd`, `reward_screen.tscn`.
- Узлы в сцене: `PascalCase` → `Zombie`, `NavigationAgent2D`, `HealthBar`.
- Переменные / функции: `snake_case` → `var move_speed`, `func take_damage()`.
- Константы: `UPPER_CASE` → `const DAWN_TIME`.
- Сигналы: прошедшее время → `signal died`, `signal fled`.
- Группы: `snake_case` → `"target"`, `"zombie"`, `"door"`.

---

## 4. Ключевые узлы (что за что)
- **CharacterBody2D** — тело персонажа (зомби, люди). `velocity` + `move_and_slide()`.
- **StaticBody2D** — неподвижное твёрдое (стены, дверь, окно).
- **CollisionShape2D** — форма столкновения (нужна каждому телу).
- **Sprite2D** — картинка. **ColorRect** — цветной прямоугольник (плейсхолдер).
- **NavigationRegion2D** — область ходьбы (запекается «Bake»).
- **NavigationAgent2D** — «штурман» на юните, считает путь A*.
- **Area2D** — триггеры/радиусы без физического отталкивания (на будущее).

## 5. Архитектура — главный принцип

**Логику держим отделяемой от движка. Контент — данными, не хардкодом.**

- **Числа баланса — в одном месте.** Общие числа боя/поведения — в autoload
  `Config` (`Config.DAWN_TIME`, `Config.HUMAN_MOVE_SPEED`, …). Статы типов —
  в `.tres`-ресурсах.
- **Типы юнитов = Resource.** `ZombieType` / `HumanType` (`class_name ... extends
  Resource`, поля `@export`). Один `.tres` на подтип в `resources/`. При спавне
  подставляем ресурс → меняются hp/скорость/урон/текстура. **Новый тип = новый
  `.tres`, БЕЗ веток `if` по коду.**
- **Одна базовая сцена юнита** (`zombie.tscn`) + данные на подтип. Не плодить
  сцену на каждый тип. Наследуемые сцены — только если тип реально отличается
  ПОВЕДЕНИЕМ (напр. плевок ядом).
- **Композиция важнее наследования.** Юнит = набор узлов-компонентов.
- **Глобальное состояние забега** — в autoload `GameState` (появится в Шаге C).
- **Перки/реликвии** — как модификаторы: не патчат код, а меняют общий объект
  бонусов забега, который читают системы при расчётах.

---

## 6. Связи между узлами
- Цели/категории — через **группы**
  (`get_tree().get_first_node_in_group("target")`), НЕ через хрупкие пути
  `get_node("../../X")`.
- События — через **сигналы** (`emit` / `signal`), не опрос каждый кадр.
  Пример: зомби умер → `died.emit()` → менеджер боя ловит и обновляет счётчик.
- Настраиваемые параметры узла — через **@export** (появятся в Inspector).

## 7. Спрайты (top-down, ракурс 3/4)
- PNG с прозрачностью. Filter=On (арт сглаженный, не пиксель), Mipmaps=Off для 2D.
- Исходники не раздувать: концепт ~300 px, юнит на экране ~40 px — можно ужимать.
- **Направление — только зеркалом** (`sprite.flip_h = ...`). НИКОГДА не вращать
  спрайты юнитов (`rotation`) — они 3/4, «лягут». *(Сейчас flip_h выключен —
  резкие развороты выглядели плохо; вернуть при нормальной анимации.)*
- Текстуру юнита брать **из данных** (`type.texture`), не жёстко из сцены —
  замена плейсхолдера на арт = смена поля в `.tres`.
- Глубина — **Y-Sort** (кто ниже — поверх). Origin «в ноги» (Sprite2D Offset
  вверх). *(Y-Sort отложен: включать только на узле-контейнере игровых объектов,
  не на корне и не там, где есть Control.)*
- Анимация (потом): `AnimatedSprite2D` / `AnimationPlayer`, кадры walk/attack на
  тип, атлас вместо отдельных файлов.

## 8. Встроенные системы Godot (использовать, не изобретать)
- **Движение/коллизии:** `CharacterBody2D` + `move_and_slide()`. Не писать
  выталкивание руками.
- **Навигация:** `NavigationRegion2D` + `NavigationAgent2D` (A* из коробки).
  Стены — в группе `navigation_polygon_source_geometry_group`. После правки стен —
  **Bake NavigationPolygon**. В `_ready` зомби: `await get_tree().physics_frame`
  перед первым запросом пути. `target_position` обновлять НЕ каждый кадр
  (раз в ~0.5 с / при смене цели) — путь дорогой.
- **Collision Layers/Masks:** разделять слои. Сейчас: слой 1 — стены/юниты/дверь;
  слой 2 — окно (зомби и люди ловят слой 2 маской, луч видимости — только слой 1).
- **Смена экранов:** `change_scene_to_packed()` или менеджер-autoload с памятью
  состояния.
- **TileMapLayer** — для больших/генерируемых карт пола (позже, не сейчас).

## 9. Производительность (орда = много юнитов)
- Навигацию НЕ пересчитывать каждый кадр у каждого. Уважать лимит зомби на карте.
- Пули/эффекты — пулить (object pooling), не создавать-удалять массово. *(Пока при
  ~36 юнитах не критично.)*
- `HealthBar` рисовать только при повреждении (зомби так и делает).
- Отключать обработку у того, что вне экрана/не нужно
  (`set_physics_process(false)`).

## 10. Правила для ИИ-помощника (горький опыт)
1. **Сначала ИЗУЧИ, потом пиши.** Прочитать `project.godot`, нужные `.gd`,
   структуру `.tscn` как текст; описать понимание; дождаться подтверждения.
2. **Правки по одному файлу, с кратким объяснением.** Разработчик — новичок в
   Godot, объяснять просто. Без массовых рефакторингов без спроса.
3. **`.tscn` в этом проекте ИИ правит** (по согласованию — работаем вместе).
   Следить за форматом: `load_steps`, `ext_resource`/`sub_resource` id, парность.
   Файл может измениться на диске между правками — перечитывать.
4. **Bake навигации, расстановку узлов мышью, регистрацию autoload** делает
   разработчик — ИИ пишет пошагово, что нажать.
5. **Числа — в `Config`/`.tres`**, не хардкодить вразброс.
6. **Всё коммитить** до крупных правок (откат: `git checkout <файл>`).
7. Godot «Files modified outside»: правил только ИИ и сцену не трогал →
   «Reload from disk»; сомнение → «Ignore» + проверить/откатить через git.

## 12. Запуск и публикация
- **F5** — главная сцена (`arena.tscn`); **F6** — текущая открытая сцена.
- Безголовый прогон: `<godot> --headless res://scenes/<scene>.tscn`.
- Публикация: **itch.io** — Project → Export → пресет Web → Export Project,
  залить содержимое как HTML5-игру. GitHub Pages — для быстрой тест-ссылки.

## 13. Диск (была проблема)
Забитый диск (>96 %) вешал тяжёлые инструменты. Держать свободным ≥ 5–10 ГБ:
`sudo apt clean`, `sudo apt autoremove`, `journalctl --vacuum-time=3days`.
