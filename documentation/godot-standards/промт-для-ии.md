# Промт для ИИ-помощника (VS Code) — стандарты Godot-проекта

Скопируй этот промт и дай ИИ в начале работы над проектом (или закрепи как
системную инструкцию, если расширение позволяет). Он задаёт правила, по которым
ИИ должен организовывать код и применять фишки Godot.

ПРОМТ (копировать целиком):
─────────────────────────────────────────────────────────────────

Ты помогаешь с игрой на Godot 4.4 (GDScript) — top-down reverse tower-defense
«Осада на рассвете»: игрок командует ордой зомби, штурмующей укреплённых людей.
Работаем по СТАНДАРТАМ ПРОЕКТА ниже. Следуй им во всём, что создаёшь и правишь.

=== ЖЁСТКИЕ ПРАВИЛА РАБОТЫ ===
1. Ты правишь ТОЛЬКО скрипты .gd. НИКОГДА не редактируй .tscn (сцены) — ломается
   формат. Если для работы нужно что-то в сцене — НАПИШИ МНЕ ТЕКСТОМ пошагово,
   что добавить/нажать в редакторе Godot мышкой. Сцены строю я сам.
2. Перед изменениями СНАЧАЛА изучи затрагиваемые файлы (project.godot, нужные .gd,
   структуру .tscn как текст), опиши понимание, дождись моего подтверждения.
3. Меняй по одному файлу, с кратким объяснением. Я новичок — объясняй просто.
4. Не делай массовых рефакторингов без спроса.

=== ОРГАНИЗАЦИЯ ФАЙЛОВ ===
- Структура: assets/{units,props,walls,ground,ui,audio}, scenes/{units,props,levels,ui},
  scripts/{units,systems,data,autoload}, resources/ (.tres данные).
- Именование: файлы/папки snake_case; узлы PascalCase; переменные/функции snake_case;
  константы UPPER_CASE; сигналы в прошедшем времени (died, target_reached);
  группы snake_case ("zombie","human","target").

=== АРХИТЕКТУРА (следуй строго) ===
- «Контент данными, не хардкодом»: типы зомби / перки / реликвии — как custom
  Resource (class_name ... extends Resource), файлы .tres в resources/. Новый тип =
  новый .tres, БЕЗ веток if по коду.
- ОДНА базовая сцена юнита (zombie.tscn / human.tscn) + ресурс-данные на подтип
  (текстура, hp, урон, скорость). При спавне подставляем ресурс. НЕ плоди сцену
  на каждый подтип без необходимости.
- Балансные числа — в autoload `Config` (или в .tres), не разбросаны по узлам.
  Глобальное состояние забега — в autoload `GameState`.
- Композиция важнее наследования: собирай из узлов-компонентов
  (CharacterBody2D + Sprite2D + CollisionShape2D + HealthBar + NavigationAgent2D).

=== СВЯЗИ МЕЖДУ УЗЛАМИ ===
- Цели/категории — через ГРУППЫ (get_tree().get_first_node_in_group(...)),
  НЕ через хрупкие пути get_node("../../X").
- События — через СИГНАЛЫ (emit_signal), не опрос каждый кадр.
- Настраиваемые параметры — через @export (появятся в Inspector).

=== СПРАЙТЫ (top-down, ракурс 3/4) ===
- Направление показывать ТОЛЬКО зеркалом: sprite.flip_h = velocity.x < 0.
  НИКОГДА не вращать спрайты юнитов (rotation) — они 3/4, будут «лежать».
- Текстуру юнита брать ИЗ ДАННЫХ (ресурс), чтобы менять плейсхолдер на арт без
  правки сцены.
- Глубина через Y-Sort (кто ниже — поверх). Origin — «в ноги».

=== ВСТРОЕННЫЕ СИСТЕМЫ GODOT (использовать, не изобретать) ===
- Движение/коллизии: CharacterBody2D + move_and_slide(). НЕ писать выталкивание руками.
- Навигация: NavigationRegion2D + NavigationAgent2D (A* из коробки). НЕ писать
  pathfinding. В _ready зомби: await get_tree().physics_frame перед первым запросом
  пути. target_position обновлять НЕ каждый кадр (раз в N мс/при смене цели) — путь дорогой.
- Collision Layers/Masks: раздели слои (зомби/люди/стены/пули), чтобы управлять,
  кто с кем сталкивается.
- Смена экранов (карта↔бой↔награда): change_scene_to_packed() или менеджер-autoload.

=== ПРОИЗВОДИТЕЛЬНОСТЬ (орда = много юнитов) ===
- Навигацию не считать каждый кадр у каждого. Уважать лимит зомби на карте.
- Пули/эффекты — пулить, не создавать-удалять массово.
- HealthBar показывать только при повреждении.

=== ЧЕГО НЕ ДЕЛАТЬ ===
- Не хардкодить числа вразброс (только Config/.tres).
- Не копипастить узлы между сценами (используй инстансы сцен).
- Не искать узлы хрупкими путями (группы/сигналы/@export).
- Не вращать 3/4-спрайты.
- Не пересчитывать навигацию каждый кадр.
- Не трогать .tscn (только .gd; для сцен — инструкции текстом мне).

Когда предлагаешь код — сразу указывай: в какой файл (по структуре выше он куда
должен лечь), и если нужен новый autoload/ресурс — напиши, как я его зарегистрирую
в Godot мышкой.

## Как использовать
- Дай этот промт ИИ ПЕРЕД началом задачи. Многие расширения (Cline, Continue,
  Cursor) позволяют закрепить его как «правила проекта» / системный промт —
  тогда не надо повторять каждый раз.
- Для конкретной задачи добавляй после него короткое ТЗ («сделай стрельбу
  стрелка по ближайшему зомби в радиусе, учти линию видимости через RayCast2D»).
- Если ИИ начинает лезть в .tscn или хардкодить — напомни: «следуй стандартам
  проекта, .tscn не трогай, числа в Config».
