# 08 — Godot: организация, спрайты, лучшие практики

Стандарты проекта «Осада на рассвете» под Godot 4.4. Цель — чтобы проект рос
чисто, а не превращался в свалку. Применять с самого начала, пока файлов мало.

═══════════════════════════════════════════════════════════════════
## 1. ОРГАНИЗАЦИЯ ФАЙЛОВ
═══════════════════════════════════════════════════════════════════

### Структура папок (целевая)
```
res://
├── assets/
│   ├── units/          спрайты юнитов (зомби, люди)
│   ├── props/          деревья, камни, бревна, декор
│   ├── walls/          куски стен, двери, окна
│   ├── ground/         тайлы пола
│   ├── ui/             интерфейс, иконки
│   └── audio/          звуки (позже)
├── scenes/
│   ├── units/          zombie.tscn, human.tscn (и подтипы)
│   ├── props/          tree.tscn, wall.tscn, door.tscn ...
│   ├── levels/         battle.tscn (сцена боя), forest_map.tscn (карта)
│   └── ui/             hud.tscn, reward_screen.tscn ...
├── scripts/
│   ├── units/          zombie.gd, human.gd ...
│   ├── systems/        чистая логика: spawn.gd, economy.gd ...
│   ├── data/           конфиги-ресурсы: балансные числа
│   └── autoload/       глобальные синглтоны (GameState, Config)
└── resources/          .tres файлы данных (типы зомби, перки, реликвии)
```

### Правило: сцена + скрипт рядом ИЛИ по зеркальным папкам
Выбери ОДНО и держись:
- Вариант «вместе»: zombie.tscn и zombie.gd в одной папке scenes/units/.
- Вариант «зеркально»: сцены в scenes/, скрипты в scripts/ по той же структуре.
Проект начинал с «вместе» (scenes/) — можно так и продолжать, главное единообразно.

### Именование (строго)
- Папки и файлы: snake_case → `zombie_fast.gd`, `reward_screen.tscn`.
- Узлы в сцене: PascalCase → `Zombie`, `NavigationAgent2D`, `HealthBar`.
- Переменные/функции в коде: snake_case → `var move_speed`, `func take_damage()`.
- Константы: UPPER_CASE → `const MAX_ZOMBIES = 20`.
- Сигналы: прошедшее время → `signal died`, `signal target_reached`.
- Группы: snake_case → `"target"`, `"zombie"`, `"human"`.

## 2. СЦЕНЫ И ПЕРЕИСПОЛЬЗОВАНИЕ
═══════════════════════════════════════════════════════════════════

### Каждый повторяемый объект = отдельная сцена (.tscn)
Зомби, человек, стена, дерево, дверь — каждый своя сцена. Спавнишь/ставишь
клоны. НЕ копируй узлы вручную по сценам.

### Composition (композиция важнее наследования)
Godot-way: собирай объект из узлов-компонентов, а не плоди подклассы.
Пример: у всех юнитов общий каркас (CharacterBody2D + Sprite2D + CollisionShape2D
+ HealthBar + NavigationAgent2D). Тип задаётся ДАННЫМИ (ресурс с числами и текстурой),
а не отдельной сценой на каждый чих.

### Один базовый юнит + данные (ключевая фишка для орды)
Вместо 8 сцен зомби — ОДНА сцена `zombie.tscn` + 8 ресурсов-данных
(fast.tres, armored.tres...). При спавне подставляешь ресурс → меняются
hp/скорость/урон/текстура. Это прямой аналог «контент данными, не хардкодом»
из «01 — Пиллары». Добавить новый тип = создать .tres, а не трогать код.

### Наследуемые сцены (Inherited Scenes) — если типы сильно разные
Если подтип реально отличается поведением (напр. Spitter стреляет ядом) —
сделай наследуемую сцену от базовой (правый клик на .tscn → New Inherited Scene)
и переопредели что нужно. Но не злоупотребляй — сперва пробуй «данные».

## 3. СПРАЙТЫ (top-down, наш случай)
═══════════════════════════════════════════════════════════════════

### Импорт
- PNG с прозрачностью. У нас вырезанные концепты — ок.
- В настройках импорта для пиксель-стиля ставили бы Filter=Off, но у нас
  сглаженный арт (не пиксель) → оставляй Filter=On (по умолчанию), Mipmaps=Off для 2D.
- Не хранить гигантские текстуры: концепты ~300px, юнит на экране ~40px —
  можно ужимать исходники, чтобы не раздувать проект/память.

### Ракурс 3/4 — НЕ вращать
Наши юниты нарисованы в 3/4 (видно лицо/спину). Направление показываем ТОЛЬКО
зеркалом: `sprite.flip_h = velocity.x < 0`. Никаких `rotation` для юнитов —
иначе «лежат и крутятся».

### Origin и глубина
- Origin/точку опоры ставим «в ноги»: у Sprite2D сдвигай Offset вверх, чтобы низ
  спрайта был точкой на земле.
- Глубина (кто перед кем): включи **Y-Sort** (узел YSort2D или свойство Y Sort
  Enabled у родителя). Тогда кто ниже по Y — рисуется поверх. Стандартно для top-down.

### Анимация (на будущее)
- Сейчас статичные PNG + лёгкий «боббинг» (колебание по Y синусом) — оживляет дёшево.
- Позже: AnimatedSprite2D или AnimationPlayer, кадры walk/attack на тип.
- Атлас (SpriteSheet) лучше отдельных файлов, когда кадров много.

### Плейсхолдер → арт без боли
Держи текстуру юнита В ДАННЫХ (ресурс), а не жёстко в сцене. Тогда замена
плейсхолдера на финальный арт = смена поля в .tres, сцену не трогаешь.

## 4. ФИШКИ GODOT, КОТОРЫЕ НАМ ПОДХОДЯТ
═══════════════════════════════════════════════════════════════════

### Autoload (синглтоны) — для глобального состояния
Создай автозагрузки (Project Settings → Autoload):
- `Config` — все балансные числа (замена config.js из Phaser). Один источник правды.
- `GameState` — состояние забега: ресурсы, открытые типы, перки, текущий узел карты.
Доступ из любого скрипта: `Config.zombie_speed`, `GameState.biomass`.

### Groups — вместо поиска по имени
Мы уже так делаем: зомби ищут группу "target". Продолжай: "zombie", "human",
"civilian". Массово: `get_tree().call_group("zombie", "die")`.

### Signals — вместо опроса каждый кадр
Зомби умер → `emit_signal("died")` → HUD ловит и обновляет счётчик. Не проверяй
всё в _process. Событийная модель чище и быстрее.

### Встроенная навигация (наш козырь)
NavigationRegion2D + NavigationAgent2D = A* из коробки. Не пиши pathfinding руками.
Помни: стены в группе запекания, Bake после изменений, await physics_frame в _ready.

### Встроенная физика
CharacterBody2D + move_and_slide() — коллизии сами. Не пиши выталкивание.
Collision Layers/Masks — раздели слои (зомби / люди / стены / пули), чтобы
контролировать, кто с кем сталкивается.

### Resources (.tres) — данные как файлы
Тип зомби, перк, реликвия — каждый custom Resource (class_name ZombieType extends
Resource). Редактируются в инспекторе, версионируются в git, грузятся по требованию.
Это ядро «контент данными».

### @export — настройка мышью
Помечай параметры `@export var speed := 120` — появятся в Inspector, правишь без кода.
Балансные крутилки — через @export или через Config-autoload.

### TileMapLayer — для больших карт (позже)
Пол леса/города мостить через TileMapLayer + TileSet, а не сотней Sprite2D.
Сейчас рано, но заложи в голове для генерируемых карт.

### Scene transitions
Смена сцен (карта леса ↔ бой ↔ награда) — через change_scene_to_packed()
или менеджер сцен-autoload, который помнит состояние.

## 5. ПРОИЗВОДИТЕЛЬНОСТЬ (орда = много юнитов)
═══════════════════════════════════════════════════════════════════

- Навигацию НЕ пересчитывать каждый кадр у каждого зомби. Обновляй target_position
  раз в N мс или при смене цели. Путь дорогой.
- Много одинаковых зомби → следи за числом узлов. Лимит на карте (20-30) из «04»
  помогает и геймплейно, и по производительности.
- Отключай обработку у того, что вне экрана/не нужно (set_physics_process(false)).
- HealthBar рисовать только при повреждении, не постоянно.
- Пули/эффекты — пулить (object pooling), не создавать-удалять массово.

## 6. GIT И ГИГИЕНА
═══════════════════════════════════════════════════════════════════

- .gitignore: `.godot/` (кэш), экспорт-артефакты. Исходники — коммитим.
- Коммить часто, маленькими шагами, до крупных правок (особенно до правок ИИ).
- Не коммить временные тесты в главную сцену.
- Диск держать свободным (>5 ГБ) — иначе инструменты виснут.

## 7. РАЗДЕЛЕНИЕ ЛОГИКИ И ДВИЖКА (сохраняем принцип из Phaser)
═══════════════════════════════════════════════════════════════════

- Числа/баланс → Config autoload или .tres, НЕ разбросаны по узлам.
- Чистая логика (экономика, расчёты урона) → отдельные скрипты systems/,
  по возможности не завязанные на конкретные узлы.
- Узлы-скрипты (zombie.gd) — тонкие: берут данные, дергают системы, двигают тело.
- Так проще тестировать, балансить и (если вдруг) переносить.

═══════════════════════════════════════════════════════════════════
## 8. ЧЕГО НЕ ДЕЛАТЬ
═══════════════════════════════════════════════════════════════════

- НЕ хардкодить числа в узлах/коде вразброс (только Config/.tres).
- НЕ плодить копипасту узлов между сценами (используй сцены-инстансы).
- НЕ искать узлы по хрупким путям get_node("../../X") — используй группы/сигналы/@export.
- НЕ вращать 3/4-спрайты (только flip_h).
- НЕ пересчитывать навигацию каждый кадр.
- НЕ давать ИИ редактировать .tscn (ломает формат) — ИИ только .gd.
- НЕ копить ассеты вместо сборки играбельного куска (правило «сначала играбельно»).
